# Basic mobile UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make dartcade usable on a phone (~390 px wide). Sign in, set up a game, and play X01 or Around the Clock with the board, dart slots, undo and next, following the phone artboards in the design canvas.

**Architecture:**

- **Simple pages** (shell, sign in, register, Play, History, Boards) adapt with Tailwind breakpoints. Desktop at `md` (768 px) and up stays exactly as it is.
- **The match screen** has a different structure on a phone, so `GameDisplay` gains a fourth layout, `phone`, next to `solo`, `duel` and `party`. It reuses the existing snippets and components, plus two small new player components.
- **Phone detection:** an `isPhone` store wraps `matchMedia`. Pure helpers (`matchLayout`, `navTabs`) hold the logic that can be unit-tested. This repo has no component-test setup, so Svelte markup is checked by `svelte-check` and by a visual pass.

**Tech Stack:** Svelte 5 (runes), Tailwind CSS v4 (tokens in `backend/frontend/src/app.css`), svelte-spa-router (hash routes), vitest (node), Lucide icons (`@lucide/svelte`).

**Spec:** `docs/superpowers/specs/2026-10-02-mobile-ui-design.md`

## Global Constraints

- **Phone breakpoint:** `max-width: 767.98px`. Tailwind's `md:` (768 px) is the desktop switch. Phone styles are the unprefixed base classes; desktop styles go behind `md:`.
- **Desktop at ≥ 768 px must look and behave exactly as before.** Every change keeps the old desktop classes behind `md:`.
- **Tap targets** are at least 44 px tall.
- **Bottom tab bar:**
  - 72 px tall plus `env(safe-area-inset-bottom)`.
  - Tabs in this order: Play, Live (only while a game is running), Boards, History. No Tournaments tab.
- **Phone header:** 56 px tall, with the board-ring mark (`BrandMark`) and the page title.
- **Design tokens:** use the Tailwind theme tokens from `app.css` (`bg-bg`, `bg-surface-1`, `bg-surface-2`, `bg-surface-active`, `bg-surface-panel`, `border-line`, `border-line-2`, `border-line-3`, `text-text`, `text-text-muted`, `text-text-dim`, `text-ink-2`, `text-ink-3`, `bg-accent`, `text-accent-fg`, `bg-live`, `text-live-text`, `bg-live-soft`, `border-line-pip`, `border-line-chip`). Fonts: `font-display` (Barlow Condensed) for numbers and titles.
- **No casts** in non-test code (strict type-aware ESLint): run `npm run lint`.
- **Run from `backend/frontend`:** `npm test`, `npm run typecheck` (tsc + svelte-check, 0 errors) and `npm run lint` must pass before every commit.
- **Commit messages** follow conventional commits (`feat(frontend): …`, lowercase subject under 72 chars) and end with:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_017DTbMKdwEpojREDdyywo96
  ```

## Spec deviation (decided while planning)

- **No component test for `GameDisplay`.** The frontend has no component-test setup (vitest runs in node, with no testing-library or jsdom). Adding one is out of scope. Instead, the layout choice is a pure function, `matchLayout`, with unit tests, and Task 7 is a visual pass in a real browser at both sizes.

## Review Focus

1. **Desktop must not change.** Any class that moved behind `md:` must produce exactly the old desktop result. A dropped class silently changes the desktop. Covered by Task 7's 1440 × 900 visual pass, and every task's self-review diffs the desktop classes.
2. **Rotating the phone or resizing across 768 px mid-game** must switch layouts without losing game state. Since `isPhone` only switches the markup branch, nothing else should change. Covered by the `isPhone` store test, which checks it follows `matchMedia` changes (Task 1), and by Task 7's resize check.
3. **Live tab with no running game:** the tab bar must not show Live. Covered by a `navTabs` test (Task 1).
4. **3 or more players on a short phone:** the other players' rows must scroll, and the board must keep at least 180 px. Covered by the `matchLayout` test (Task 1) and Task 7's 6-player check.
5. **A game without a board (manual entry) on a phone:** the entry panel must fit the width and stay reachable. Covered by Task 7's manual-game check.

`backend/frontend/src/lib/viewport.ts`:

```ts
import { readable, type Readable } from 'svelte/store'

/** Below Tailwind's `md`: the phone layouts. */
export const PHONE_QUERY = '(max-width: 767.98px)'

type ChangeListener = (e: { matches: boolean }) => void
export type MatchMediaFn = (query: string) => {
  matches: boolean
  addEventListener(type: 'change', cb: ChangeListener): void
  removeEventListener(type: 'change', cb: ChangeListener): void
}

/** Whether `query` matches, kept up to date (false where there is no matchMedia). */
export function mediaStore(query: string, mm: MatchMediaFn | null): Readable<boolean> {
  if (!mm) return readable(false)
  const list = mm(query)
  return readable(list.matches, set => {
    const onChange: ChangeListener = e => set(e.matches)
    list.addEventListener('change', onChange)
    return () => list.removeEventListener('change', onChange)
  })
}

/** The viewport is phone-sized: layouts CSS alone can't switch read this. */
export const isPhone: Readable<boolean> = mediaStore(
  PHONE_QUERY,
  typeof window !== 'undefined' && typeof window.matchMedia === 'function' ? q => window.matchMedia(q) : null,
)
```

(If the linter rejects the `MediaQueryList` → `MatchMediaFn` assignability in the arrow, keep the arrow — `window.matchMedia(q)` returns a `MediaQueryList`, whose `addEventListener('change', …)` takes a `MediaQueryListEvent` listener; if TS complains, type the parameter as `MatchMediaFn` and wrap: `q => { const l = window.matchMedia(q); return { matches: l.matches, addEventListener: (_t, cb) => l.addEventListener('change', cb), removeEventListener: (_t, cb) => l.removeEventListener('change', cb) } }`. No casts.)

```ts
/** How the match screen lays out its players: one phone layout, or by player count. */
```

```ts
import { readable, type Readable } from 'svelte/store'
import { api } from '$lib/api'

/** The id of the user's running game, if any. */
export function pickActive(sessions: { id: string; status: string }[] | undefined): string | null {
  return sessions?.find(s => s.status === 'active')?.id ?? null
}

/** The running game, loaded when first used (the banner and the tab bar share it). */
export const activeSessionId: Readable<string | null> = readable<string | null>(null, set => {
  api.GET('/api/sessions')
    .then(({ data }) => set(pickActive(data?.sessions)))
    .catch(() => { /* no game shown */ })
})
```
