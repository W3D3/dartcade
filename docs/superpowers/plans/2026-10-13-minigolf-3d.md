# Minigolf 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Minigolf games play with server-side 3D physics (Rapier) and a 3D match screen, with the 2D game behind the `gamemode.minigolf.flat` flag.

**Architecture:** The bench's ground and 3D physics move into `backend/src/shared/minigolf/3d/` and become the game's default engine. The ground is a Rapier heightfield; the cup is a contact filter over the hole. The game module picks the engine from its config (`physics: '3d' | '2d'`). The browser draws the snapshot with the bench's `Hole3D`, grown into the match screen's hole view.

**Tech Stack:** TypeScript, Rapier (`@dimforge/rapier3d-deterministic-compat` 0.21.0), three.js 0.186, Svelte 5, vitest, Playwright, OpenFeature (existing flags).

**Spec:** `docs/superpowers/specs/2026-10-13-minigolf-3d-design.md`

## Global Constraints

- Rapier is `@dimforge/rapier3d-deterministic-compat`, the same exact version in `backend/package.json` and `backend/frontend/package.json` (pin it, no caret), as nape-js is.
- The server is the authority: the browser never decides where a ball ends; it draws `path`.
- `simulateShot3d` is synchronous and pure; only `initPhysics3d()` is async. It throws a clear error if called before init.
- Heights: a slope rises `strength / G` per mm (`G = 9810` mm/s²); terrain adds mesas. All code uses `heightAt` from `shared/minigolf/3d/ground.ts`.
- A full-power 3D shot on every test hole costs under 20 ms on the dev machine (checked by a test).
- New flag `gamemode.minigolf.flat`, off by default, on through `FLAGS_ON`. Config `physics` defaults to `'3d'`; `'2d'` only with the flag.
- No initials on balls in 3D: balls are told apart by the seat colour (`seatColor`).
- The shot preview is a straight dotted line from the ball, as long as the putt rolls on flat felt (`power × maxRoll`); it is not simulated and passes through walls. In 2D and 3D.
- Minigolf hasn't shipped: no compatibility with old lobbies, games or snapshots.
- Lockfiles: `backend/` uses npm 11, `backend/frontend/` `npx -y npm@10`; don't commit unrelated lockfile churn.
- Commits: conventional, atomic, each builds and passes tests; end with the session's attribution lines.

## Review Focus

1. A ball resting on a ramp steeper than friction never "rests": the sim must still end (it rolls to the bottom); a ball on a slope gentler than friction stays put. Test in Task 2.
2. A cup on raised ground (on a mesa) and a ball passing over the cup at speed: holed only when it drops, never because it's below the cup's height elsewhere. Test in Task 2.
3. Ball contact in 3D: two balls in the cup, a knocked ball dropping in, a knocked ball rolling off a cliff. Test in Task 4.
4. A browser without WebGL (or a lost GL context) on the match screen: the 2D view still plays the game. Test in Task 8.
5. A hole JSON edited on the bench with `terrain` but invalid numbers (zero widths, NaN heights): rejected by `validateHole`, never reaching Rapier. Test in Task 1.

```ts
/** The ground's heights on a grid `step` mm apart over the outline's bounds, row by row. */
export function heightGrid(hole: Hole, step: number): { x0: number; y0: number; nx: number; ny: number; heights: Float32Array } {
  const xs = hole.outline.map(p => p[0])
  const ys = hole.outline.map(p => p[1])
  const [x0, y0] = [Math.min(...xs), Math.min(...ys)]
  const nx = Math.ceil((Math.max(...xs) - x0) / step)
  const ny = Math.ceil((Math.max(...ys) - y0) / step)
  const heights = new Float32Array((nx + 1) * (ny + 1))
  for (let j = 0; j <= ny; j++) for (let i = 0; i <= nx; i++) heights[j * (nx + 1) + i] = heightAt(hole, [x0 + i * step, y0 + j * step])
  return { x0, y0, nx, ny, heights }
}
```
